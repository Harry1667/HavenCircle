## 1. TDX 運輸資料流通服務（tdx.transportdata.tw）—— 交通事故／路況

**這是什麼**：交通部主導的全國運輸資料整合平台，涵蓋公路、鐵路、公車等多種運具資料，其中「路況資訊 v2」分類含國道、省道、縣市道路的即時路況與事件公告。

- **平台首頁**：https://tdx.transportdata.tw/
- **API 文件（Swagger）**：https://tdx.transportdata.tw/api-service/swagger
- **路況資訊 v2 文件**：https://tdx.transportdata.tw/api-service/swagger/basic/7f07d940-91a4-495d-9465-1c9df89d709c
- **官方範例程式**：https://github.com/tdxmotc/SampleCode

**要不要申請**：要。訪客模式僅能瀏覽基礎服務、每日限量（官方頁面對這個數字的兩處說法不一致，20 次或 50 次/日，以平台當下顯示為準）。要程式化呼叫需：
1. 至 https://tdx.transportdata.tw/register 註冊會員（Email 驗證＋等待審核）
2. 會員中心取得 `Client Id` / `Client Secret`
3. 用 OAuth2 Client Credentials 流程換 Access Token（`POST /auth/realms/TDXConnect/protocol/openid-connect/token`）
4. 呼叫 API 帶入 Token

實測直接呼叫（未帶金鑰）回傳 `HTTP 401 Valid API Key Required`，證實一般路況/事故端點確實需要金鑰。免費，屬政府資料開放授權；一般會員即可申請，不需企業資格。

**資料格式**：JSON 或 XML（`$format` 參數），支援 OData 查詢語法（`$select`／`$filter`／`$top` 等）。

**更新頻率（官方 GitBook 已確認：https://motc-ptx.gitbook.io/tdx-zi-liao-shi-yong-kui-hua-bao-dian/data_notice/traffic_data/update_frequency ）**：

| 資料項目 | 更新頻率 |
|---|---|
| VD 車輛偵測器動態路況 | 1 分鐘 |
| CMS 可變資訊標誌 | 2 分鐘 |
| 發布路段即時路況 | 1 分鐘 |
| eTag 旅行時間 | 5 分鐘 |
| **News（事故／壅塞／施工／交管公告，`NewsCategory=2` 即事故）** | **不定期** |

**涵蓋範圍**：國道（`/Freeway`）、省道（`/Highway`）、縣市道路（`/City/{City}`，約 20 個縣市代碼），全國覆蓋度佳。

**注意**：真正結構化、含肇因/傷亡細節的正式交通事故統計（A1/A2 表）門檻更高，需另外書面申請計畫送交通部審查（此點為二手資訊，未在官方頁面逐字確認）。這條不建議追，一般路況/事故公告端點就夠用。

**實用性評估：中**。理由：事故公告本質是交控中心人工發布的文字說明，更新頻率「不定期」、無精確經緯度與肇因分類，無法保證秒級/分鐘級自動偵測；但作為「壅塞路段、道路施工」的背景資訊，格式標準、全國覆蓋、免費，適合做粗粒度的路況提示，不適合做核心的「即時事故警報」。

## 2. 治安／犯罪資料 —— 部分可行但不即時

### 2-A. 警政署刑案統計（data.gov.tw）

- **官方網址**：https://data.gov.tw/dataset/14200 （犯罪資料）、https://data.gov.tw/dataset/13166 （犯罪統計數據）、https://data.gov.tw/dataset/177118 （114年整體治安情勢）、警政署 OPEN DATA 總覽 https://www.npa.gov.tw/ch/app/data/list?module=wg051&id=2177
- **申請門檻**：免申請，政府資料開放授權條款第 1 版，直接下載
- **資料格式**：CSV／PDF，**無 API**
- **更新頻率**：季更（犯罪資料集）；年度治安情勢為年度 PDF 報告
- **實用性評估：低** —— 案類 × 縣市層級的落後統計，無座標、無單一案件明細，無法用來做「附近發生案件」推播。

### 2-B. 165 全民防騙網／打詐儀錶板

- **官方網址**：https://165.npa.gov.tw/、https://165dashboard.tw/
- **申請門檻**：免申請、免帳號，但是**網頁單筆人工查詢介面**，非 API。原本 data.gov.tw 上有「詐騙 LINE ID」資料集（https://data.gov.tw/dataset/78432 ）已於 2024/11 下架，官方公告改導向 165 打詐儀錶板查詢，學術用途需另向刑事警察局書面索資。
- **資料格式**：無批次下載，僅網頁單筆查詢
- **更新頻率**：查詢結果應為即時，但無法程式化批次抓取
- **實用性評估：低－中** —— 概念上最貼近「即時治安警示」，但沒有開放 API，最多只能做「使用者輸入電話號碼→跳轉 165 查詢頁」的淺整合，無法自動比對推播。

### 2-C. 各縣市警察局

- 未查到任何縣市警察局提供「即時案件通報」API（例如即時刑案地圖）。台北市警察局有治安統計視覺化網頁（https://police.gov.taipei/ ），性質同樣是統計儀表板。22 縣市未逐一查證，若後續需要可再展開，但預期同樣不會有即時案件 API。

## 3. EMIC 應變管理資訊雲

**結論：EMIC 本體是政府防救災人員專用系統，沒有對外公開 API；民眾端「全民防災e點通」也沒有開發者 API。**

- **EMIC 入口**：https://portal2.emic.gov.tw/ —— 登入對象是地方政府災害應變中心編組人員、鄉鎮市區公所指揮官，一般民眾/開發者無法申請開發用存取權。
- **全民防災e點通**（EMIC 民眾端 App／網頁）：https://bear.emic.gov.tw/MY2/ —— 提供災情訊息、防災地圖、避難所查詢、個人化防災警示，但這是消費端服務，**沒有對外開放給第三方開發者的 API**。
- **實用性評估：不可行**（本體）／**低**（e點通，只能導流使用者去下載官方 App，無法整合進自家 App）。

## 4. 1991 報平安 —— 此路不通，已停用

- **原網址**：https://www.1991.tw/ —— 直接 WebFetch 該網址回傳 `getaddrinfo ENOTFOUND www.1991.tw`，網域已無法解析，這本身就是停用的直接證據。
- **現況**：「1991 急難通信平臺」（電話語音留言、網路留言板）已於 **民國 111 年 12 月 31 日（2022/12/31）停止服務**。多個地方公所公告（例：台南官田區公所 https://guantian132.tainan.gov.tw/News_Content.aspx?n=6838&s=8547118 ）確認同一停用日期，並引導民眾改用「全民防災e點通」的平安通報功能。
- **實用性評估：不可行＋原因**：服務已終止兩年多，網域失效，沒有任何整合空間。若 App 想做「報平安」功能，只能自建或導流至官方 e點通 App。

## 5. 台電停電資訊

- **停電查詢網頁**（給民眾查詢用，非 API）：https://service.taipower.com.tw/nds/ndsWeb/ndft112.aspx —— 逐一檢視頁面表單結構，未發現公開、免驗證碼即可呼叫的 JSON/XHR 端點；查詢送出需輸入圖形驗證碼，不適合程式化整合。
- **data.gov.tw 上兩個相關資料集**：
  - 計畫性工作停電：https://data.gov.tw/dataset/26144 —— ZIP 壓縮檔，**每日更新**（當天無排定停電的區處會延用前次內容，需留意此陷阱）
  - 配電系統重大事故停電速報案件記錄：https://data.gov.tw/dataset/122741 —— CSV，**每年更新一次**，是歷史彙整，不是即時事故通報
- **申請門檻**：兩個資料集皆免申請，政府資料開放授權條款第 1 版
- **資料格式**：ZIP／CSV，非 JSON、非即時輪詢端點
- **實用性評估：低** —— 家庭安全警報需要「現在是否停電/有停電風險」的即時訊號，但台電公開資料分別是「每日排程」（非即時觸發）與「年度回溯」（延遲極大），無法支撐即時警報情境。唯一接近即時的查詢系統是給人看的網頁、有 CAPTCHA 擋自動化，若強行爬取有違反服務條款風險，不建議依賴。

## 6. 環境部空氣品質 API（data.moenv.gov.tw）

**這是什麼**：環境部（原環保署，2023/8 升格改名，網址沿革 opendata.epa.gov.tw → data.epa.gov.tw → 現行 data.moenv.gov.tw）的開放資料平台，涵蓋空品即時監測、預報、歷史資料。

- **官方網址**：https://data.moenv.gov.tw
- **申請流程**：https://data.moenv.gov.tw/api_term 完成會員註冊 → 系統寄發 API Key 至註冊 Email → 呼叫時帶入 Key。**免費**，未見任何收費說明。
- **資料格式**：JSON／XML／CSV（`format=json` 等參數指定）
- **範例 API**：`https://data.moenv.gov.tw/api/v2/AQX_P_432?api_key={your-api-key}&limit=1000&sort=ImportDate%20desc&format=json`
- **更新頻率**：AQI（含 PM2.5／PM10／O3／SO2／CO／NO2 等 24 欄位，資料集代碼 `AQX_P_432`）**每小時更新一次**，同步自 airtw.moenv.gov.tw 空氣品質監測網。另有 `AQX_P_488`（歷史）、`AQF_P_01`（預報）。
- **涵蓋內容**：AQI/PM2.5 在同一平台確認無誤。**異味通報**：未在此平台找到明確、獨立的即時陳情資料集（只查到地方政府零散年度統計）。**輻射監測**：**不在同一平台**，是行政院原能會/核安會另外提供（https://www.aec.gov.tw ，全台 63 站、每 5 分鐘更新，但此細節為二手資訊未逐一驗證申請門檻）。
- **實用性評估：中高**。技術門檻低（email 註冊即可拿 Key）、JSON 格式方便串接、每小時更新，適合做「空品達橘色以上提醒配戴口罩/減少戶外活動」這類日常健康提醒，對過敏/氣喘/長輩族群有實用價值。但更新頻率是小時級、語意上屬於「健康建議」而非「生命安全事故」，建議歸類在「日常健康提醒」模組，不要跟地震/淹水等緊急示警放在同一優先層級。

## 7. 疾管署 CDC 開放資料平台

- **官方網址**：https://data.cdc.gov.tw （CDC 自建的獨立 CKAN 平台，非 data.gov.tw 子集）
- **申請門檻**：**免申請、免費、免 API 金鑰**。`/pages/developer` 頁面上的「登入」欄位標註「僅限本署內部使用」，一般查詢動作（`action` 類 GET）依 CKAN 慣例是公開的。實測範例：`https://data.cdc.gov.tw/api/action/datastore_search?resource_id=xxx&limit=5`
- **資料格式**：CSV／JSON 為主，部分資料集另有 XML/XLSX，靜態下載檔掛在 `od.cdc.gov.tw`，也可透過 CKAN `datastore_search` 做結構化查詢
- **更新頻率**：依資料集而異（直接呼叫 CKAN `package_search` 拉出 `updated_freq` 欄位確認）：
  - 急診症候群監視（手足口病、腸病毒、流感、腹瀉等 RODS）：每日
  - COVID-19 相關統計：每日
  - 結核病資料：每日
  - 急性腹瀉 RODS：每週
  - 旅遊醫學處方箋：每月
  - 抗藥性統計（AMR）：不定期
- **技術風險（實測發現）**：直接 curl／WebFetch 連線 `data.cdc.gov.tw` 與 `od.cdc.gov.tw` 皆出現「SSL certificate problem: unable to get local issuer certificate」，伺服器端憑證鏈不完整。iOS 的 `URLSession`／ATS 很可能也會擋這個連線，若要接入建議先在實機/模擬器測試，必要時需处理憑證例外或等官方修復。
- **實用性評估：中** —— 技術門檻低、有結構化 API，適合做疫情儀表板/趨勢圖表；但 SSL 憑證問題是實際的接入障礙，且下一節確認「示警」用途已被 NCDR 涵蓋，CDC 平台的價值主要在補統計細節，不在即時警報。

### NCDR 傳染病示警的上游是否為 CDC？—— 是，不用另接

透過代理成功渲染 NCDR 的機關對照表頁面（https://alerts.ncdr.nat.gov.tw/alertMessageAPI.aspx ，原生 WebFetch/curl 因該站為 JS SPA 只回傳空殼，改用渲染代理確認內容），明確列出 12 個發布機關中包含：

> **疾病管制署 — 傳染病**：「疾病管制署蒐集重要傳染病疫情及可能引發疫情的相關資訊，提醒加強防範，防止其蔓延」

**結論**：NCDR 的傳染病示警發布機關本來就是 CDC，NCDR 只是把它轉發、標準化成 CAP 格式的中介層。既然 App 已整合 NCDR 43 項示警（含傳染病類別），**不需要另外整合 CDC 開放資料平台來做「示警推播」**。若之後需求變成「疫情趨勢圖表」（例如某縣市登革熱歷史病例數趨勢），CDC 平台仍有獨立價值，因為 NCDR 只轉發「示警等級事件」，不含完整統計時間序列。

## 8. 地方政府開放資料平台（以台北市 data.taipei 為代表）

- **官方網址**：https://data.taipei/
- **申請門檻**：多數資料免申請，平台提供線上預覽、檔案下載及 Open API 介接。個別資料集細部門檻未逐一查證，可能有例外。

**具「即時／準即時」性質、且是 NCDR／data.gov.tw 都沒有的獨有資料**（已查證存在）：
- **台北市 CCTV 設施**：可查詢每支路口監視器詳細資訊並直接觀看即時畫面 —— 全國性平台沒有的即時影像串流入口
- **台北市疏散門即時監測**：標註為 Open API，屬防災設施即時狀態類，全國性平台查無對應項目
- **台北市今日施工資訊**：準即時的道路施工/封閉資訊
- **台北市降雨積水模擬圖**：防災預警用途

**需區分**：防空避難處所清冊、可供避難收容處所一覽表是**靜態清單**，不是即時狀態；「避難所目前是否開放/是否額滿」的即時佔用狀態，本次未查到對應欄位，**未確認**是否存在。

**其他縣市**：未查到新北市、高雄市有獨立、具名的市級即時安全資料開放平台（可能存在但未被搜尋索引到，**未確認**）。民間整合平台如 tw.live 涵蓋新北/高雄路口攝影機，但非官方 API。

**與 data.gov.tw、NCDR 的差異互補**：data.gov.tw 是全國性資料的「目錄/入口」，多為靜態清冊；NCDR 專注「重大災害示警事件」；data.taipei 這類地方平台的互補性在於「市級基礎設施的即時/準即時狀態」（CCTV、疏散門、施工資訊），這是前兩者都不會覆蓋的顆粒度。

**實用性評估：中高**。若 App 主打台北都會區使用者，CCTV 即時畫面與疏散門即時監測是獨特的即時資料，值得評估整合；但若目標是全國通用，地方平台覆蓋不均（外縣市可能沒有對等資料集）會造成功能不一致，需額外評估。

## 總結與建議動工順序

1. **環境部空氣品質 API**：技術門檻最低（email 註冊即可），每小時更新，JSON 格式，適合先做「日常健康提醒」模組，跟緊急示警分開呈現。
2. **data.taipei 路口 CCTV／疏散門即時監測**：若 App 現階段以台北都會區為主力使用者，這是市級即時設施狀態的獨有資料，值得納入地圖圖層；若目標全國通用，優先度降低。
3. **TDX 路況資訊**：可作為「壅塞/施工路段」的背景圖層，但事故公告更新頻率「不定期」，不要當作核心即時警報依賴。
4. **治安（165）、台電停電、EMIC、1991**：查證後確認都不具備「可程式接取的即時資料」條件，暫不投入開發資源；165 最多做查詢頁面導流。
5. **疾管署 CDC**：不用為了「示警」單獨整合（NCDR 已涵蓋上游），若未來要做疫情趨勢圖表功能再考慮，且需先處理其 SSL 憑證鏈問題。

**信心等級**：本輪查證的官方頁面確認度整體為**中高**——TDX、環境部空品、CDC、data.taipei 主要結論均有官方頁面或實測（curl/API 呼叫）佐證；EMIC、1991、台電因服務性質本身就是「網頁/內部系統/已停用」，查證重點在確認「此路不通」而非細節參數，可信度同樣高。少數細節（TDX 頻率限制數字、CDC 平台 rate limit、原能會輻射平台申請門檻、新北/高雄是否有獨有即時平台）標注為未確認，需要時可再深入查證。
