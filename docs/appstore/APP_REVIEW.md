# 安心圈 HavenCircle — 三位一體審查報告

> 審查日期：2026-07-16
> 審查者角色：資深產品經理 × 挑剔的真實客戶（要推薦給爸媽的 35 歲子女）× 學校 App 競賽評審
> 審查方式：五個分頁＋新手教學逐一截圖（存於 `.audit/review/`），對照 Swift 源碼與線上 API 實測

## 總評

這是一個**架構誠實、產品守則清晰、且已接上真實政府災害資料**的原型，完成度遠超一般學生作品：NCDR 民生示警確實透過 `havencircle.looptw.com` 中繼站即時抓取（實測回傳 12 筆相關事件、`source: official-api`、時間戳新鮮），提醒決策（`AlertPolicy`）把「為何收到／未驗證不推播／時段外不打擾」集中在單一決策點且理由直接顯示給使用者，治安圖層還主動加了「統計≠即時安全」的倫理免責。**但它離「敢推薦給爸媽用」還有一段距離**：最致命的是「附近緊急資源（避難所／醫院）是寫死的示例座標，導航按鈕會真的把人導去假地點」；其次是「即時性」——目前只有回到前景才刷新，沒有伺服器推播，一個號稱「關鍵時刻收得到」的警報 App，關鍵時刻其實收不到。以下依三視角分列，章內按嚴重度排序。

**嚴重度定義**：P0＝崩潰或誤導安全資訊｜P1＝核心流程斷點｜P2＝體驗問題｜P3＝打磨

# 第一章：資深產品經理視角

> 關注：產品定位、功能完整度、流程斷點、與 Life360／Apple 尋找的差異化。

### 差異化定位（先講結論）
本產品的差異化其實**很鋒利、也站得住腳**：Life360／Apple 尋找的核心是「追蹤家人即時位置」，本產品刻意反其道——**不追蹤任何人的位置**，只監看「官方災害示警是否落在家人生活圈（住家／長輩家）附近」。這對「不想被子女定位、但子女想知道長輩住處是否有災情」的華人家庭情境是精準的。問題是：**這個定位目前只寫在 Onboarding 文案裡，App 內沒有一處把它變成可感知的體驗或行銷鉤子**，白白浪費了最強的賣點。

### P1－1　核心承諾「即時通知」目前並不即時
- 位置：`Views/AppTabs.swift:55-58`（僅 `scenePhase == .active` 時 `EventPipeline.refresh`）、`Services/BackgroundRefresh.swift`（有 `BGAppRefreshTask` 但無伺服器 APNs 推播）
- 問題：資料只在「使用者主動打開 App 回到前景」或「系統偶爾給的背景配額」時才更新。一個災害警報 App 的價值 100% 建立在「事情發生的當下推到鎖定畫面」，但目前後端（Mac Mini 爬蟲→Oracle）只做到「抓資料存 JSON 給 App 拉」，最後一哩的 APNs 主動推播尚未接（`SESSION_NOTES.md` 亦自陳階段 4 未開始）。爸媽把 App 裝著，地震發生時手機安靜無聲，等他下次打開才看到——這是產品定位的自我否定。
- 修法：優先把 Oracle 端接 APNs（App 上傳「關心的行政區」→ 伺服器比對新示警 → 對命中的裝置發推播）。這是本產品從「能 Demo」到「能上線」的唯一關鍵路徑，優先級應高於任何 UI 打磨。

### P1－2　服務範圍（雙北）與資料範圍（全國）不對稱，且對使用者無聲
- 位置：`Support/Districts.swift:6-18`（行政區清單只有台北市＋新北市）、`Models/RegionAlert.swift:76-83`（`matchedCircles` 靠 `district` 比對）、`Onboarding/OnboardingView.swift:337-339`（`guessDistrict` 只認雙北）
- 問題：NCDR provider 抓的是全國示警（無地區過濾），但生活圈的 `district` 只能命中雙北。**住在台中、高雄的爸媽，區域警報永遠比對不到、永遠不會收到通知，App 卻不會告訴他**。他會以為「沒收到＝沒事」，實際是「根本沒在保護他」——對安全 App 這是誤導性的沈默失效。
- 修法：短期在 Onboarding 與設定明確標示「區域警報比對目前僅支援雙北」；中期把 `DistrictBoundaries` 擴到全國（資料量不大，內政部有全國行政區界圖開放資料）。

### P2－3　「重大交通事故」是一等公民類別，卻自認沒有即時資料源
- 位置：`Views/Settings/SettingsInfoViews.swift:23-27`（自陳「即時交通事故與治安事件目前沒有政府公開的即時資料源」）對照 `Models/LifeCircle.swift:76`（`traffic` 仍在 `defaultSelection` 預設接收）、`EventEditorView`／`SafetyMapView` 圖層都把它當正式選項
- 問題：產品一邊在說明頁承認「這類收不到真資料」，一邊在生活圈預設、地圖過濾、事件類型選單裡把它當成正常可用的類別。使用者會勾選「重大交通事故」然後永遠等不到——功能承諾與資料現實脫鉤。
- 修法：要嘛把無真實資料源的類別標成「即將推出／目前僅供手動測試」，要嘛從預設選取移除，避免製造「勾了卻永遠沒反應」的空承諾。

### P2－4　「附近更新」沒有距離上限，被全國事件灌成雜訊
- 位置：`Views/Map/SafetyMapView.swift:507-531`（`nearbyStrip` 只排序不設上限）、`Views/Events/EventListView.swift:25-29`（`elsewhere` 分類同樣無距離門檻）
- 問題：實測（截圖 `22-tab2.png`）家在信義區，地圖底部「附近更新」第一張卡片竟是「省道台9線 227K 道路封閉，距離住家 145.7 公里」。安全狀態橫幅邏輯正確（`attentionCount` 只算生活圈內確認事件，正確顯示「沒有需要注意的事件」），但底部卡片列與提醒中心「其他區域動態」把 145 公里外的花蓮路況當「附近」推到眼前，稀釋真正相關的訊號。
- 修法：對「其他區域／附近更新」加距離上限（例如生活圈半徑的 N 倍或縣市邊界），超過的收進「全台其他示警」的可展開次級清單。

### P2－5　生活圈只能新增、不能編輯
- 位置：`Views/Family/CircleEditorView.swift:48`（只有「新增生活圈」，全檔無編輯路徑）
- 問題：Onboarding 若地址搜尋失敗會退回「台北市南港區」預設座標（`OnboardingView.swift:317`），使用者事後想修正地址或半徑，只能刪掉重建。對「幫爸媽設定住家位置」這種一定會設錯一兩次的情境，沒有編輯功能是明顯的流程斷點。
- 修法：`CircleEditorView` 支援傳入既有 `LocalLifeCircle` 進入編輯模式（沿用同一表單，改 upsert）。

### PM 補充觀察（正向，供保留）
- 提醒中心分類（需要注意／持續確認中／其他區域動態／已結束）與 `AlertPolicy` 的判斷邏輯**嚴格一致**（`EventListView.swift:18-39`），不會出現「標籤說需要注意、實際不在生活圈」的名實不符——這是很多同類產品做不到的紀律。
- 「暫停提醒」是真的暫停（與早期原型的假旗標不同），且暫停時事件仍顯示、只是不推播，狀態在地圖橫幅明示（`SafetyMapView.swift:478-482`）。

# 第二章：挑剔的真實客戶視角（要把 App 推薦給爸媽的 35 歲子女）

> 我要把它裝到我媽手機上。我對每個看不懂、按不到、不放心的地方開砲。

### P1－1（可視為 P0）　「附近避難所／醫院」是假的，導航會把我媽帶去錯的地方
- 位置：`Services/EmergencyResourceStore.swift:5-7`（自陳「示例資料：知名地標與醫院的概略座標」）、`Views/Events/EventDetailView.swift:99-139`（資源列＋「導航」按鈕真的用 Apple Maps URL 開導航到這些假座標）、`SafetyMapView.swift:270-288`（地圖避難所／醫院圖層同一份假資料）
- 問題：這是最讓我不敢按下推薦鍵的一條。事件詳情頁明明白白列出「最近避難所：XXX，約 300 公尺」並給一顆「導航」按鈕，按下去 Apple 地圖真的會開始導航——但那個座標是寫死的示例地標，不是真的避難所。火災或地震時，我媽照著導航走去一個根本不是收容所的地方，這比「沒有這個功能」更危險。UI 雖有一行免責（`EventDetailView.swift:103-105`），但那是 `caption2` + `.tertiary` 的灰色小字，慌亂中沒人會看。
- 修法：**上線前這是硬門檻**。三選一：(a) 接內政部「避難收容處所」與衛福部「急救責任醫院」開放資料（雙北先做，資料可內嵌成 bundle JSON，不需後端）；(b) 在接上真資料前，直接隱藏「導航」按鈕與距離數字，只保留「撥打 119／查詢政府避難地圖連結」；(c) 至少把免責升級成無法忽略的醒目樣式並移到按鈕正上方。現況（真按鈕＋假資料＋小字免責）是最糟組合。

### P1－2　我媽住台中，這 App 對她其實沒在運作，卻不會講
- 位置：同 PM P1－2（`Districts.swift` 僅雙北）
- 問題：以客戶角度重述——我照著設定幫我媽把住家設在台中，一切看起來正常（有地圖、有生活圈圈圈），但區域警報永遠不會命中。我會一直以為「安靜＝平安」，直到某天出事才發現它從頭到尾沒保護過她。對安全 App，「無聲的失效」是最不可原諒的。
- 修法：非雙北生活圈要在家人頁／設定明確標示「此地區暫不支援區域警報比對」。

### P2－3　要按右上角那顆小圖示才能新增家人，我找了很久
- 位置：`Views/Family/FamilyListView.swift:10-43`（`members` 為空時只剩 `InviteFamilySection`，`ForEach(members)` 不渲染任何東西，沒有任何「尚未新增家人／點這裡新增」的引導）
- 問題：第一次進家人頁，畫面空空的（截圖 `23-tab3.png` 只有「邀請家人需要先登入 iCloud」和我自己一個人），新增本機家人的入口藏在導覽列右上角的 `person.badge.plus` 小圖示。長輩自己絕對找不到，我幫忙也要找一下。
- 修法：空狀態放一張明確的 `ContentUnavailableView` 附「新增家人」大按鈕。

### P2－4　我按了「邀請家人」卻好像沒反應，不知道成功了沒
- 位置：`Views/Family/SafetyCheckInView.swift:134-143`（`startShare` 失敗只 `AppLog.cloudError`，無任何使用者可見的錯誤或成功提示）、`SettingsView.swift:399-401`（「允許通知」按鈕按下無反饋）
- 問題：邀請家人失敗時我完全不知道發生什麼事，畫面沒動；允許通知按下去也沒有任何「已開啟」的確認。對不熟手機的長輩，「按了沒反應」＝「這 App 壞了」。
- 修法：所有非同步動作補上 loading／成功／失敗的可見狀態（Toast 或行內狀態列）。

### P2－5　高溫警報卻顯示一朵打雷下雨的雲，我看了會混淆
- 位置：`Views/Alerts/RegionAlertViews.swift:11`、`:42`、`SafetyMapView.swift:448`（三處都寫死 `cloud.bolt.rain.fill`）
- 問題：截圖 `10-tab0-alerts.png` 裡「高溫警報：高溫資訊」旁邊是一個下雨打雷的圖示。地震、火災、停水也全都是這個雨雲圖。對快速掃一眼判斷「這是什麼災害」的使用者，圖示傳達了錯誤的第一印象。
- 修法：建一個 `kind → SF Symbol` 對應表（高溫→`thermometer.sun.fill`、地震→`waveform.path.ecg`／`house.and.flag`、火災→`flame.fill`、淹水→`drop.fill`…），三處共用。

### 客戶補充抱怨
- **P3**　我想改我媽住家的地址，發現只能刪掉重設（同 PM P2－5）。
- **P3**　「回顧」頁一則 7/15 的「重大火災事件通報」到今天還標「進行中」（截圖 `21-tab1.png`），火災都過一天了還在進行中，看起來像資料沒更新（實際是跟著 NCDR 的 expires 走，但使用者不知道，觀感是 App 很舊）。位置：`Models/SafetyEvent.swift:91-96`（`isEnded` 依 `expiresAt`）。建議對超過合理時長的事件加「資料截至 X」輔助說明。

# 第三章：學校 App 競賽評審視角

> 評分維度：創新性、完成度、技術深度、社會價值、Demo 效果。

## 3.1 亮點（會加分的地方，先講）
- **真資料，不是假 Demo**：NCDR 民生示警經自建爬蟲（Mac Mini）→ Oracle 中繼 → App 即時拉取，實測線上 API 正常回傳真實示警。多數學生作品到這步都是塞死資料，這是硬實力。
- **產品倫理成熟度罕見**：治安圖層主動標「統計≠即時安全、避免標籤化社區」（`SafetyMapView.swift:105-116`），只塗高於中位數的行政區（四分位分級，`:196-221`）；災害示警刻意用「行政區塗層」而非大頭針，因為強風豪雨影響的是整區、釘一點會誤導（`:144-146`）。這種克制與思辨是評審會眼睛一亮的。
- **技術深度**：`AlertPolicy` 單一決策點、SwiftData 本地優先、CKShare 家庭共享＋已讀回條、`cloudKitDatabase:.none` 避免鏡像衝突、輕量遷移欄位預設值——都是有 iOS 工程 sense 的設計。

## 3.2 會被扣分／評審當場會質疑的問題（按嚴重度）

### P1－1　「附近緊急資源」假資料是 Demo 地雷
- 位置：同第二章 P1－1（`EmergencyResourceStore.swift:5-7` 等）
- 評審會問：**「你這個避難所是真的資料嗎？導航會導到哪裡？」** 只要有評審點開任一事件、按下「導航」，就會發現導去的是寫死地標。當場破功，且對「安全」主題是硬傷。
- 修法：Demo 前務必接真資料（雙北避難所／醫院開放資料可內嵌，不需後端），或 Demo 時完全不展示此功能。

### P1－2　「即時推播」在 Demo 上無法演示，而這正是評審最想看的
- 位置：同第一章 P1－1（無 APNs 伺服器推播）
- 評審會問：**「地震發生的那一秒，我的手機會怎樣？現場示範一下推播。」** 目前答不出來——只能說「打開 App 會刷新」。對災害警報 App，這是最該有的「Demo 高潮」，缺席會讓完成度大打折扣。
- 修法：見 3.3 第 1 名。

### P2－3　區域警報圖示系統性錯誤，Demo 螢幕上很顯眼
- 位置：`RegionAlertViews.swift:11,42`、`SafetyMapView.swift:448`
- 評審會問：**「為什麼高溫警報是下雨的圖？」** 投影幕放大時這種 icon 與內容不符特別刺眼，會被解讀成「細節沒做完」。
- 修法：`kind → SF Symbol` 對應表，一次修三處。

### P2－4　地圖有多層塗色卻沒有圖例（legend）
- 位置：`SafetyMapView.swift:185-229`（紅／橙／黃嚴重度色、靛藍治安四分位深淺），但畫面無任何顏色說明
- 評審會問：**「地圖上這些顏色深淺各代表什麼？」** 沒有圖例，評審無法自行解讀，你得口頭解釋——好的 Demo 應該讓畫面自己說話。
- 修法：地圖角落加可收合的圖例卡（嚴重度色階＋治安級距）。

### P2－5　差異化定位沒有在產品內被「演」出來
- 問題：最強的賣點（不追蹤位置、只看官方示警落在家人生活圈）只存在於 Onboarding 文字。Demo 若不主動講，評審會把它誤認成又一個 Life360 仿製品。
- 修法：做一頁「為什麼不是 Life360」的對照（App 內「關於」頁或 Demo 簡報），把「零位置追蹤 × 官方災害源 × 長輩友善」講成一句話。

### P3 級（打磨，Demo 前有空再修）
- 家人頁、回顧頁部分空狀態缺文案（`FamilyListView` 全檔、`HistoryView.swift:32-48`）。
- 避難所／醫院地圖標記缺 `accessibilityLabel`（`SafetyMapView.swift:270-288`），無障礙不完整（社會價值維度可加分項，補齊 VoiceOver 是低成本高印象分）。
- 「暴力事件僅高可信度提醒」文案與實際類別「公共安全」不一致（`SettingsView.swift:397` vs `LifeCircle.swift:69-77`）。
- `LocalLifeCircle.encryptedAddress` 欄位名叫「加密」實為明文（`LifeCircle.swift:8-9`）——被問到隱私時這個命名會反咬一口，建議 Demo 前改名或補 TODO 註記，別讓「我們有加密住址」變成講不出口的漏洞。
- 註解漂移：`NotificationScheduler.swift:88-89`、`SmokeTest.swift:40` 仍寫「沒有背景更新／會命中 mock 事件」，與現況（已有 `BackgroundRefresh`、已全面改真資料）不符，交接／被追問實作時容易自打嘴巴。

## 3.3 「還缺什麼能顯著提升得獎機率」——排序後的建議清單

1. **接上 APNs 真實推播，做出「示警發生 → 手機當場跳通知」的 Demo 高潮**（最高投報率）。這一步把產品從「查詢工具」變成「守護工具」，也是評審最想看、目前最缺的一環。後端骨架（爬蟲＋Oracle）已在，只差最後一哩。
2. **把假的緊急資源換成真開放資料（雙北避難所／急救醫院）**。移除當前最大的安全可信度破口，且可內嵌 JSON、不需後端，成本低、止血效果大。
3. **雙裝置實機跑通 CKShare 安否回報，作為情感點的 Demo**：「爸媽一鍵回報我平安 → 子女手機即時看到已讀」。這是本產品最有溫度、最能打動評審社會價值的一幕，勝過任何技術炫技。
4. **一輪視覺止血**：修 icon 對應表、加地圖圖例、加「附近」距離上限、補關鍵空狀態。讓 Demo 螢幕上沒有一眼可見的破綻。
5. **明確的差異化敘事**：一張「vs Life360／Apple 尋找」對照 + 一句電梯簡報（零位置追蹤的長輩災害守護），把定位優勢講清楚。
6. **服務範圍誠實化**：全國行政區覆蓋，或在 UI 明確標示「僅雙北」。避免評審一句「那我阿嬤在台南能用嗎」就問倒。
